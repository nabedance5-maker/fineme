Me Scan 診断ロジック解説
なぜこの設計なのか、どう動くのか

PTおよび掲載者（ガイド）向けに、Finemeの中核機能「Me Scan」の設計思想・質問構造・スコア計算・マッチングへの接続を解説します。男性トラック（Fineme）・女性トラック（Fineme Belle）共通の仕組みです。

Version: v14_8axis_growing-map　／　2026-08-07　／　Fineme

00
Design Philosophy

Me Scanは「タイプ分類」ではなく、
「変容の経路を生成するエンジン」です。

「タイプ診断」との根本的な違い

一般的な外見診断は「あなたはXXタイプ」と分類して終わります。Me Scanはそうではありません。

目的は「この人が変容の旅を通じて、今どの軸に注力すべきか」を継続的に指し示すことです。最初の一手を示すだけでなく、旅が進むにつれて次に向かうべき方向を更新し続ける羅針盤を生成します。結果は一人ひとり異なり、同じ状態でもゴールの違いによって経路が変わります。

診断データが担う3つの役割

① New Me Navi（地図）の生成 — 現在地・理想・ギャップを8軸で可視化

② Fineme Compass（羅針盤）の決定 — 最初に動かすべき軸を1つ示す

③ 掲載者マッチングのスコアリング — ユーザーの文脈と掲載者のプロフィールを照合

診断結果は「見てわかる地図」として設計されており、ユーザーは何度でも見返します。Finemeにとって診断は入口ではなく、ユーザーとの継続的な関係の基盤です。

02
8 Axes — 8軸の設計

Tier構造で「変わりやすさ」を設計

8軸にはTier（1〜4）が設定されています。Tierは「その軸の変化がもたらすインパクトの大きさと速さ」を表し、Compassの計算に使われます。

💪 体型・ボディ Tier 1 / 速効度3

筋肉・体脂肪・姿勢。変化に時間がかかるが、変わったときのインパクトは最大。パーソナルジムが対応。

✂️ 眉毛 Tier 1 / 速効度5

顔の印象を決定づける。プロに1回頼むだけで変化が出る「最速の投資」。眉毛サロンが対応。

👔 服・コーデ Tier 1 / 速効度5

全身印象の60〜70%を決める。トータルコーディネートの提案で即日変化が出る。

💇 髪・ヘア Tier 1 / 速効度4

清潔感・若見えに直結。AGA分岐あり（薄毛はカテゴリ別に分岐して対応ガイドへ接続）。

✨ 肌・ニキビ・エステ Tier 2 / 速効度3

清潔感・近距離の印象に影響。スキンケア習慣の構築からプロのケアまで幅広い。

🪒 脱毛・ムダ毛 Tier 2 / 速効度3

ひげ・体毛の処理。清潔感への寄与度が高く、脱毛サロン・クリニックが対応。

🦷 歯・口元 Tier 3 / 速効度2

笑顔・近距離コミュニケーションに影響。ホワイトニング（即効）から矯正（長期）まで。

💅 爪 Tier 4 / 速効度2

細部の清潔感。ハンドケア・ネイルサロン対応。恋愛軸の問いはなし（近距離印象に特化）。

Tier 1（体型・眉・服・髪）はFinemeの「基盤」カテゴリです。この4軸に同時に問題がある場合、速効度の高い「眉」か「服」を最初の一手として優先する設計になっています。「最速で自信を感じられる変化」を起点にすることが、変容継続につながるからです。

03
Score Calculation — スコア計算

変容ベクトル（gap）と
Compassの決定ロジック

① 変容ベクトルの計算

各軸の「現在地スコア」と「理想スコア」の差分がベクトル（gap）です。

current_score = Q3の行動選択から自動算出
none→1／concerned→2／self→3〜3.5（選択した行動のカバー率で細分化）／pro→4
ideal_score = 「変えたい度」の回答（1〜5）。無回答時は max(current_score, 3)
gap = max(0, ideal_score − current_score)
※ gap が 0 = 現状で十分、またはすでに理想以上

② Compass（最初の一手）の決定：priority_order

gap > 0 の軸を以下の優先順位でソートし、1位が「Compass」になります。

優先順位1位: Tier が低いほど優先（Tier 1 → 4）
同Tierの場合: gap が大きいほど優先
同gapの場合: 速効度（SPEED値）が高いほど優先
SPEED値: 眉=5, 服=5, 髪=4, 体型=3, 肌=3, 脱毛=3, 歯=2, 爪=2

例：体型(gap=3)と眉(gap=2)が同じTier 1にある場合、gapは体型が大きいが、速効度は眉(5)>体型(3)なのでCompassは体型を指す。ただしユーザーは「最初の一手」を8軸チップで上書きできます（Compass override機能）。

04
深掘り（任意・結果画面から1軸ずつ）

結果画面から`?deepen=軸ID`で誘導。
1軸につき最大2問（脱毛・爪は1問）

「来た道（path_type）」はもう質問しない

旧フローは経路を自己申告で聞いていましたが、現在はQ3で選んだ行動項目の組み合わせから自動判定されます（下記4分類）。深掘りで実際に聞くのは①自己視点（self_view）と②恋愛への影響（love_impact）の最大2問だけです。

Q3の行動選択から自動判定される4パターン（path_type）

その軸とこれまでどんな経緯で関わってきたかを4分類で自動判定します。これは掲載者との照合に使われる最重要データです。「初めての人（virgin）」と「挫折経験者（quit）」では、必要なガイドの種類が根本的に違います。

virgin
🌱 未着手・無関心
入門・ゼロからのスタートを得意とするガイドとマッチ。不安の解消が先決。
quit
🔄 試したが続かなかった
「なぜ続かなかったか」の原因分析と再設計が得意なガイドとマッチ。
blind
🤔 自己流・客観評価なし
「方向性の見直し」「客観的な評価」を提供できるガイドとマッチ。
lapsed
😴 以前はやっていた
「再起動・モチベーション維持」が得意なガイドとマッチ。

深掘りの問い① — 客観視（self_view）

「他者から自分がどう見えていると思うか」の推測を取得します（better / accurate / worse / unknown）。

worse（自分より悪く見えているかも）や unknown（わからない）は強い不安の指標です。New Me Mapの「障壁分析」セクションに使われ、「まず客観評価を受けることが先決」というアドバイスの根拠になります。

深掘りの問い② — 恋愛への影響（love_impact）

「その軸への不安が恋愛・出会いの場面で影響したことがあるか」（often / sometimes / rarely）。

love_impactが「often（よくある）」の軸は、New Me Naviで恋愛バッジとして強調表示されます。また、外見への不安と恋愛の結びつきはFineme全体の動機文脈として機能します。脱毛・爪の2軸のみこの問いをスキップし1問構成になります（近距離印象には影響するが恋愛への文脈が薄いため）。

05
Outputs — 診断が生み出す3つのアウトプット

「地図」「羅針盤」「ロードマップ」が
ユーザーの変容を継続的に支える

🧭
New Me Navi
8軸レーダーチャート、変容ベクトルリスト、プロマッチング。「自分だけの地図」として保存・参照される。
🧭
Fineme Compass
変容の旅を通じて「今最も注力すべき軸」を指し示す羅針盤。最初の一手を示すだけでなく、旅が進むにつれて向かうべき方向が更新される。ユーザーによる手動override機能あり。
🛤️
New Me Map
8軸をルート状に並べた変容ロードマップ。Compassが指す軸だけ全幅展開、他は折りたたみ表示。通っている店舗・費用を記録する「New Me Log」（診断を経ずに使える3つ目の入口）とも軸IDで接続される。

この3つは「地図を渡す→羅針盤で方向を示す→ロードマップで道を歩く」という連続した体験として設計されています。Compassは最初の一手を示すだけでなく、旅が進むにつれてどの軸に向かうべきかを指し示し続けるものです。ユーザーがNew Me Map上でステータスを「ひと段落」にした軸はCompassの対象から外れ、次に優先すべき軸へ自動で切り替わります（動的Compass）。診断は「完了するもの」ではなく、変容の旅全体を通じてユーザーと共に在り続けます。

06
AI Matching — 掲載者とユーザーの相性判定

「チェックボックス」ではなく
「文章をAIが読み取る」マッチング

なぜチェックボックスではないのか

「得意なきっかけ」を選ぶ方式では、掲載者は全項目にチェックを入れることができてしまいます。これでは「誰にでも合います」という状態になり、ユーザーにとって意味のある相性判定になりません。

Finemeは、掲載者が実際の顧客について文章で書いた内容をClaudeが読み取ることで、本当に合う人を精度高く判定する設計を採用しています。文章を丁寧に書けば書くほど、ターゲットに近いユーザーに届きやすくなります。

掲載者が書く6つのフィールド

ダッシュボード「サービス設定」タブの「AIマッチングプロフィール」欄に以下を記述します。

target_desc
狙いたいターゲット像
どんな人に来てほしいか、狙っている客層を自由に記述する。
ideal_client_desc
よく来るお客様の状況・背景
実際に多く来ている顧客の状況・職業・年齢・生活背景などを自由に記述する。
client_before_state
来る前の典型的な状態
初回来店前の悩みや状態のパターン。どんな課題を抱えてくる人が多いか。
transformation_pattern
よく起きる変化のパターン
このサービスを通じてどんな変化が起きるか。ビフォーアフターの典型的なストーリー。
best_fit_desc
特に向いている人・状況
どんな人・タイミングに最もマッチするか。逆に向かない人についても書くと精度が上がる。
description
サービス全体の説明
サービス単位のbefore/afterを含む一般的な紹介文。

AIが生成する構造化データ

「AIで分析する」ボタンを押すと、Claudeがキャッチコピー・理念・ガイドメッセージ・強みも含めたプロフィール全文を読み取り、以下の構造化データを自動生成します。

フィールド 内容 マッチングへの使われ方
suitable_triggers 向いているきっかけ（AI推論） ユーザーのtriggerと照合。一致でスコア+10
handles_failure_patterns 対応できる失敗パターン（AI推論） ユーザーのfailure_patternと照合。一致でスコア+10
target_axes 対応できる変容軸（AI推論） ユーザーのCompass軸・優先軸と照合
goal_alignment ゴールとの親和性タグ（自由語） ユーザーのゴール文脈との重み付けに使用
personality_tags 向いているユーザーの特徴（自由語） 掲載者公開ページに「こんな方に向いています」として表示
summary 誰に向いているかの1〜2文 掲載者公開ページに「来る方のリアルなストーリー」として表示

AI分析済みの掲載者はスコアにボーナスが加算されます。分析後にプロフィールを更新した場合、再度「AIで分析する」ボタンを押すことで最新の内容に更新されます。チェックボックスの設定は、AI未分析の場合のフォールバックとして機能します。

07
Area Matching — エリアマッチング

距離（Haversine）ベースで
近くにいるユーザーに優先表示

なぜ距離マッチングが必要なのか

外見磨きサービスは「通い続けられる距離にあること」が継続率に直結します。Me Scanの診断結果との相性が高くても、遠距離では予約に至りません。エリアマッチングはユーザーと掲載者の物理的な距離をスコアに組み込み、「合う × 通える」という条件を両立させます。

ユーザーの位置情報取得フロー

診断結果ページの下部に「LocationPrompt」が任意表示され、エリア設定を促します。設定方法は2種類あります。

A
方法 A — 現在地から自動設定
GPS → Nominatim → 座標保存

ブラウザのGeolocation APIでGPS座標を取得 → Nominatim（OpenStreetMap）に送信して都道府県・市区町村のテキストを取得 → GPS座標（lat/lon）をそのまま端末のlocalStorageに保存。
座標は端末内にのみ保存され、サーバーには送信しません。マッチングAPIが呼ばれた瞬間にクライアントから座標を添付し、サーバー側でスコアを計算します。

Geolocation API Nominatim（OSM） lat/lon → localStorage
B
方法 B — 手動選択（都道府県 → 市区町村）
セレクトUI → 市区町村重心座標 → 保存

ドロップダウンで都道府県 → 市区町村の順に選択 → Nominatimで選択した市区町村の重心座標を取得 → lat/lonをlocalStorageに保存。
マイページからいつでも変更可能（引越し対応）。都道府県は`profiles.prefecture`、市区町村は`profiles.city`としてSupabaseに保存されます（ログイン時）。

都道府県セレクト 市区町村セレクト Nominatim重心座標

Haversine距離スコアリング（/api/providers）

APIリクエスト時にユーザーのlat/lonが添付されている場合、掲載者のlat/lonとのHaversine距離を計算し、距離に応じたボーナスをスコアに加算します。

距離 ≤ 10km → +8pt
徒歩・自転車・近接エリア — 最も強いボーナス
距離 10〜30km → +5pt
電車で通える範囲
距離 30〜50km → +2pt
少し遠いが通える可能性あり
距離 > 50km → +0pt
距離ボーナスなし
座標未設定の場合 → テキストフォールバック
同都道府県+4pt / 同市区町村+4pt（合計最大+8pt）

アフィリエイト掲載者は距離ボーナス対象外です。オンライン完結・全国対応のサービスとして扱われるため、エリアに関わらず均等にスコアリングされます。

掲載者の住所とジオコーディング

掲載者ダッシュボード「プロフィール設定」タブで都道府県 → 市区町村 → 番地以下の3段階で住所を入力します。保存時にNominatimが自動でジオコーディングを実行し、lat/lonをprovidersテーブルに保存します。番地以下はユーザーには非公開（マッチング精度向上のみに使用）。最寄り駅・アクセスは別途テキストで入力し公開されます。

テーブル カラム 内容
profiles（ユーザー） prefecture 都道府県（手動選択時に保存）
profiles（ユーザー） city 市区町村（手動選択時に保存）
providers（掲載者） prefecture 都道府県（セレクト入力）
providers（掲載者） city 市区町村（セレクト入力）
providers（掲載者） address 番地以下の詳細住所（非公開）
providers（掲載者） lat 緯度（Nominatim自動取得）
providers（掲載者） lon 経度（Nominatim自動取得）

ユーザーのlat/lonはlocalStorageにのみ保存されます（DBには保存しない）。これはプライバシーを守りつつ、「現在地に近い掲載者を優先表示」という体験を実現するための設計です。座標情報はマッチングAPIへのリクエスト時にのみ利用され、セッション終了後も端末内に保持されます（引越し時にマイページから更新可）。
