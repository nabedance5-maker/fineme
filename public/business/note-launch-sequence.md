## 1. でおの「ゼロ→成功ナラティブ」パッケージ

一貫して使う物語の骨（vision.md / Memory.md と整合）：

```
【過去】20歳頃、顔もセンスもお金もスキルもゼロの非モテだった
   ↓
【転機①】外見に向き合い、変われる道があると知った（→ 現役モデルへ）
   ↓
【転機②】その"変わる方法を渡す事業"(Fineme)を、AIで丸ごと自動化して運営
   ↓
【現在】特別な才能もお金もない普通の僕でも、AIで事業を回して収益化できてる
   ↓
【読者へ】「才能じゃなくてやり方」。その手順を公開します
```

- Threads＝この物語を毎日少しずつ撒く（型②物語・型④実演）
- フロントnote＝「やり方（汎用）」、メインnote＝「その具体事例＝Fineme収益化の全手順」

## 2. 販売シーケンス（順序を守る＝実績ゼロでメインを出さない）

### Phase 0：準備（🟢/🟡・でおGO前でも進む）
- [ ] Threadsアカウント文言（bio・最初の10投稿）を threads-playbook.md から用意
- [ ] フロントnote本文を清書（note-front-draft.md ベース）
- [ ] メインnoteは「構成の型」まで用意（実数欄は空で待機）

### Phase 1：Threads立ち上げ（🔴 開設・投稿はでおGO）
- [ ] アカウント開設・bio案A設定
- [ ] 型②物語・型③気づき・型④実演を中心に毎日投稿（まず"人となり"と信頼）
- 目安：フォロワーが動き出すまで1〜2週

### Phase 2：フロントnote公開（🔴 公開・課金はでおGO）
- [ ] フロントnote公開（¥500・「残り◯部」表記）
- [ ] Threadsで型⑤予告＋型①実績を投入
- [ ] 売れたら**実数を即Threadsに反映**（「◯日で◯部！」）＝燃料化
- 目安：最初の数十部で「◯部達成」の数字を作る → bioを案Bに差し替え

### Phase 3：メインnoteへシフト（🔴 公開・課金はでおGO）
- [ ] フロントの実数をメインnoteのsocial proof欄に反映して清書完了
- [ ] メインnote公開（¥1,500〜・段階値上げ・残部）
- [ ] Threadsは型①実績＋型⑤予告を販売期に集中
- [ ] 部数マイルストーンで値上げ

### Phase 4：ループ運用
- [ ] 売れた実数・感想を次のThreads素材＆値上げ根拠に
- [ ] フロント＋メインをマガジン束ね検討
- [ ] KPIを note-threads-strategy.md §4 に週次ログ

## 3. 7日ミニ・ローンチ（Phase 2→3 を回すときの型）

| Day | Threads | note |
|---|---|---|
| 1-2 | 型②物語で予熱「近々ヤバいの出します」 | — |
| 3 | 型③気づきで中身の片鱗 | — |
| 4 | 型⑤予告「明日公開！最初の◯部は特価」 | — |
| 5 | 型⑤公開告知＋型①（初速の数字） | 公開 |
| 6 | 型①実績更新「もう◯部！」 | — |
| 7 | 型⑤締め「残り◯部で値上げ」 | 値上げ予告 |

## 4. でおレビュー・チェックリスト（公開前）

- [ ] 各note・投稿が「稼ぎ方＝読者が自分も稼げると感じる」を提示しているか
- [ ] 最初の商品がフロント（汎用AI収益化）になっているか（AI×外見磨きコンテンツnoteにすり替わっていないか）
- [ ] 実数はすべて本物か（虚偽実績なし）
- [ ] 始点を嘲笑っていないか（vision ガードレール）
- [ ] 機密（APIキー・内部パス）が漏れていないか
- [ ] 文体が memory `user-deo-writing-style` に沿っているか
