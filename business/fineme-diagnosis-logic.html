Me Scan 診断ロジック解説
なぜこの設計なのか、どう動くのか

PTおよび掲載者（ガイド）向けに、Finemeの中核機能「Me Scan」の設計思想・質問構造・スコア計算・マッチングへの接続を解説します。

Version: v9_me_scan　／　2026-03-24　／　Fineme

00
Design Philosophy

Me Scanは「タイプ分類」ではなく、
「変容の経路を生成するエンジン」です。

「タイプ診断」との根本的な違い

一般的な外見診断は「あなたはXXタイプ」と分類して終わります。Me Scanはそうではありません。

目的は「この人が変容の旅を通じて、今どの軸に注力すべきか」を継続的に指し示すことです。最初の一手を示すだけでなく、旅が進むにつれて次に向かうべき方向を更新し続ける羅針盤を生成します。結果は一人ひとり異なり、同じ状態でもゴールの違いによって経路が変わります。

診断データが担う3つの役割

① New Me Map（地図）の生成 — 現在地・理想・ギャップを7軸で可視化

② Fineme Compass（羅針盤）の決定 — 最初に動かすべき軸を1つ示す

③ 掲載者マッチングのスコアリング — ユーザーの文脈と掲載者のプロフィールを照合

診断結果は「見てわかる地図」として設計されており、ユーザーは何度でも見返します。Finemeにとって診断は入口ではなく、ユーザーとの継続的な関係の基盤です。

01
Scan Flow — 全体フロー

4つのフェーズで
「文脈 → 現在地 → 来た道 → 行動スタイル」を取得

1
Phase 1 — Context
文脈・動機の把握（5問）

変わりたいきっかけ（trigger）、ゴールの4層（何の場面で / 何をどう変えたいか / 変わった後のビジョン / 具体的な状況）を取得します。
「なぜ今か」を最初に聞くことで、後続の質問に感情的な意味を持たせます。

trigger goal_scene goal_change goal_vision scene
2
Phase 2 — Baseline
7軸の現在地・理想スコア（9〜11問）

体型・眉・服・髪・肌・歯・爪の7軸について、現状の関わり方（care_level）と理想スコア（1〜5）を取得します。
care_levelは「気にしていない（1点）→ 気にはなっている（2点）→ 自己流でやっている（3点）→ プロに頼んでいる（4点）」の4段階。
髪軸にはAGA分岐（薄毛・抜け毛の懸念）が独立した1問として存在します。

care_levels ideal_levels aga_concern / aga_status
3
Phase 3 — Path Scan
7軸×3問の「来た道・客観視・恋愛紐付け」（最大21問）

Phase 2でスコアが入った各軸に対し、3つの角度で深掘りします。
① 来た道（path_type） — その軸とどんな経緯で関わってきたか（virgin/quit/blind/lapsed）
② 客観視（self_view） — 他者から自分がどう見えていると思うか（better/accurate/worse/unknown）
③ 恋愛への影響（love_impact） — その軸への不安が恋愛・出会いに影響したことがあるか（体型・眉・服・髪・肌・歯のみ）

path_types self_views love_impact
4
Phase 4 — Behavior Style
行動スタイル・コンテキスト（4問）

失敗パターン（failure_pattern） — 過去の挫折の文脈（継続不足・自己流・情報過多など）
スタイル優先軸（style_priority_top） — 「説明重視×自己判断」「相談重視×通いやすさ」「おまかせ×指示がほしい」「慎重派×継続重視」の4タイプ
緊急度（urgency） — いつまでに変わりたいか
予算感（budget） — 月の投資可能額

failure_pattern style_priority_top urgency budget
02
7 Axes — 7軸の設計

Tier構造で「変わりやすさ」を設計

7軸にはTier（1〜4）が設定されています。Tierは「その軸の変化がもたらすインパクトの大きさと速さ」を表し、Compassの計算に使われます。

💪 体型・ボディ Tier 1 / 速効度3

筋肉・体脂肪・姿勢。変化に時間がかかるが、変わったときのインパクトは最大。パーソナルジムが対応。

✂️ 眉毛 Tier 1 / 速効度5

顔の印象を決定づける。プロに1回頼むだけで変化が出る「最速の投資」。眉毛サロンが対応。

👔 服・コーデ Tier 1 / 速効度5

全身印象の60〜70%を決める。トータルコーディネートの提案で即日変化が出る。

💇 髪・ヘア Tier 1 / 速効度4

清潔感・若見えに直結。AGA分岐あり（薄毛はカテゴリ別に分岐して対応ガイドへ接続）。

✨ 肌・エステ・脱毛 Tier 2 / 速効度3

清潔感・近距離の印象に影響。スキンケア習慣の構築からプロのケアまで幅広い。

🦷 歯・口元 Tier 3 / 速効度2

笑顔・近距離コミュニケーションに影響。ホワイトニング（即効）から矯正（長期）まで。

💅 爪 Tier 4 / 速効度2

細部の清潔感。ハンドケア・ネイルサロン対応。恋愛軸の問いはなし（近距離印象に特化）。

Tier 1（体型・眉・服・髪）はFinemeの「基盤」カテゴリです。この4軸に同時に問題がある場合、速効度の高い「眉」か「服」を最初の一手として優先する設計になっています。「最速で自信を感じられる変化」を起点にすることが、変容継続につながるからです。

03
Score Calculation — スコア計算

変容ベクトル（gap）と
Compassの決定ロジック

① 変容ベクトルの計算

各軸の「現在地スコア」と「理想スコア」の差分がベクトル（gap）です。

current_score = care_level の変換
none → 1　／　concerned → 2　／　self → 3　／　pro → 4
ideal_score = ユーザーが選んだ理想スコア（1〜5）
gap = max(0, ideal_score − current_score)
※ gap が 0 = 現状で十分、またはすでに理想以上

② Compass（最初の一手）の決定：priority_order

gap > 0 の軸を以下の優先順位でソートし、1位が「Compass」になります。

優先順位1位: Tier が低いほど優先（Tier 1 → 4）
同Tierの場合: gap が大きいほど優先
同gapの場合: 速効度（SPEED値）が高いほど優先
SPEED値: 眉=5, 服=5, 髪=4, 体型=3, 肌=3, 歯=2, 爪=2

例：体型(gap=3)と眉(gap=2)が同じTier 1にある場合、gapは体型が大きいが、速効度は眉(5)>体型(3)なのでCompassは体型を指す。ただしユーザーは「最初の一手」を7軸チップで上書きできます（Compass override機能）。

04
Phase 3 — 3問の設計意図

「来た道」「客観視」「恋愛紐付け」の
それぞれが何のためにあるか

問い① — 来た道（path_type）

その軸とこれまでどんな経緯で関わってきたかを4分類で取得します。これは掲載者との照合に使われる最重要データです。「初めての人（virgin）」と「挫折経験者（quit）」では、必要なガイドの種類が根本的に違います。

virgin
🌱 未着手・無関心
入門・ゼロからのスタートを得意とするガイドとマッチ。不安の解消が先決。
quit
🔄 試したが続かなかった
「なぜ続かなかったか」の原因分析と再設計が得意なガイドとマッチ。
blind
🤔 自己流・客観評価なし
「方向性の見直し」「客観的な評価」を提供できるガイドとマッチ。
lapsed
😴 以前はやっていた
「再起動・モチベーション維持」が得意なガイドとマッチ。

問い② — 客観視（self_view）

「他者から自分がどう見えていると思うか」の推測を取得します（better / accurate / worse / unknown）。

worse（自分より悪く見えているかも）や unknown（わからない）は強い不安の指標です。New Me Naviの「障壁分析」セクションに使われ、「まず客観評価を受けることが先決」というアドバイスの根拠になります。

問い③ — 恋愛への影響（love_impact）

「その軸への不安が恋愛・出会いの場面で影響したことがあるか」（often / sometimes / rarely）。

love_impactが「often（よくある）」の軸は、New Me Mapで恋愛バッジとして強調表示されます。また、外見への不安と恋愛の結びつきはFineme全体の動機文脈として機能します。爪軸のみhas_love=falseで、この問いをスキップします（近距離印象には影響するが恋愛への文脈が薄いため）。

05
Output Data — 診断結果データ

localStorage / Supabaseに保存される
全フィールドと使われ方

フィールド名内容と使われ方
trigger変わりたいきっかけ（matching_app / love / career / self / friend_reaction）。掲載者の suitable_triggers と照合してマッチングスコアに加点。
goal_scene / goal_change / goal_visionゴール3層。New Me Mapのヒーローコピー生成に使用。「誰の前で」「何をどう」「変わった後どうなる」。
transform_vectors7軸の {current, ideal, gap, tier, care_type, path_type, self_view, love_impact} オブジェクト。レーダーチャート・ベクトルリスト・Compassすべての根拠。
priority_ordergap>0の軸をTier→gap→速効度でソートした配列。[0]がCompass。
compass_firstpriority_order[0]のコピー。Compassのデフォルト値。overrideで上書き可能。
failure_pattern過去の失敗パターン（too_busy / no_direction / quit_fast / info_overload / ongoing）。掲載者の handles_failure_patterns と照合。
style_priority_top4スタイルのうち最優先（explanation_autonomy / consultation_accessibility / delegate_directive / cautious_continuity）。New Me Naviのトーン変更に使用予定。
urgency変わりたい期間（1ヶ月以内 / 3ヶ月 / 半年 / 焦っていない）。Compassの「急ぎ注記」表示に使用。
aga_concern / aga_statusAGA（薄毛）の懸念・現状。hair軸の結果とは別に保持。AGAガイドへの専用接続に使用。
axis_progress各軸の進捗状態を管理するJSONB（例: {"body":"active","hair":"done"}）。"done"になった軸はCompassの候補から除外される（動的Compass）。LocalStorage + Supabase（profiles.axis_progress）に二重保存。
step_doneNew Me Naviの各軸ステップ完了チェック状態をJSONBで保存（例: {"body_s0":true,"body_s1":true}）。LocalStorage + Supabase（profiles.step_done）に二重保存。デバイスをまたいで同期される。
06
Outputs — 診断が生み出す3つのアウトプット

「地図」「羅針盤」「ロードマップ」が
ユーザーの変容を継続的に支える

🗺️
New Me Map
7軸レーダーチャート、変容ベクトルリスト、ゴール4層、プロマッチング。「自分だけの地図」として保存・参照される。
🧭
Fineme Compass
変容の旅を通じて「今最も注力すべき軸」を指し示す羅針盤。最初の一手を示すだけでなく、旅が進むにつれて向かうべき方向が更新される。ユーザーによる手動override機能あり。
🛤️
New Me Navi
7軸をルート状に並べた変容ロードマップ。Compassが指す軸だけ全幅展開、他は折りたたみ表示。停留所が左右交互にずれるジグザグ設計。ルートパターン3種（推奨・印象インパクト・取り組みやすさ）から選択可。

この3つは「地図を渡す→羅針盤で方向を示す→ロードマップで道を歩く」という連続した体験として設計されています。Compassは最初の一手を示すだけでなく、旅が進むにつれてどの軸に向かうべきかを指し示し続けるものです。ユーザーがNew Me Navi上でステータスを「ひと段落」にした軸はCompassの対象から外れ、次に優先すべき軸へ自動で切り替わります（動的Compass）。診断は「完了するもの」ではなく、変容の旅全体を通じてユーザーと共に在り続けます。

07
Matching — 診断データとマッチングの接続

診断データが掲載者スコアリングに
どう使われるか

診断が終わると、ユーザーのデータは/api/providersへのクエリパラメーターとして渡され、掲載者の総合スコアを計算します。

診断フィールドマッチングへの影響
trigger掲載者の suitable_triggers（きっかけ配列）に含まれていれば +8点
failure_pattern掲載者の handles_failure_patterns（失敗パターン配列）に含まれていれば +8点
compass_first (軸)その軸に対応するカテゴリを掲載者が持っていれば +12点（例：body軸 → gym カテゴリ）
priority_order (上位3軸)掲載者のサービスがその軸の対象軸であれば各 +5点（最大+15点）

ユーザーデータ以外のスコア要素

マッチングスコアはユーザーとの一致だけでなく、掲載者のプロフィール充実度（哲学・ビジョン・写真・スタッフ等）とサービスの内容充実度（変容の約束・Before/After等）も積算します。テキトーに2項目だけ設定しても上位には出ない設計です。
